## How this is measured

Every PR lands on main as a merge commit, and every time the harness brings a PR branch up to date it merges main into the branch, so each rebase leaves a sync merge in the PR's history. Each sync merge committed in the window, on a PR merged in the window or on an unmerged branch, is replayed with `git merge-tree` under the `.gitattributes` of the commit the merge ran in, so a file that was `merge=union` at the time and merged cleanly is not a conflict. Conflicts counts the distinct PRs (and unmerged branches whose tip conflicts with the ref as it stood when the tip was committed) where a replay conflicted on the file, and Rebases counts the distinct PRs where both main and the branch had changed the file since their merge base, conflict or not. A branch rebuilt by force-push or by `git rebase --onto` leaves no sync merge, so it is not counted here, and a shallow clone is refused rather than undercounted.

## Correction (BH-5236, 2026-10-11)

The version of this file generated on 2026-10-07 had counts that were too high. That run had three faults in `bin/conflict-hotspots.sh`:

- The script counted one sync merge again under every ref that reached it. A merge-queue copy (`mergify/merge-queue/*`) and a retry branch (`ticket/bh-N-r2`) each added the same conflict one more time.
- The script scanned the local `mergify/*` refs. The old table had 12 `mergify/merge-queue/` entries (4 distinct ids) in the PRs column of 3 rows: `worker/jobs/schema.sql`, `bin/blocked-resolver.sh` and `bin/merge-conductor.sh`.
- The script scanned local remote-tracking refs that origin had deleted. The checkout never ran `git fetch --prune`, so it kept stale `origin/mergify/merge-queue/*` refs (293, a count from the BH-5236 ticket, not measured in this build).

BH-5236 fixed all three. Each sync merge and each branch tip now counts once. `mergify/*` refs are skipped unless `--include-mergify` is given. One `git ls-remote` call skips a local ref that origin no longer has. The weekly `conflict-hotspots-fleet` lane now fetches with `--prune`.

The table above is regenerated with the fixed script, over the same window (`--now 1791335073`). The run used a new full clone of `example-org/cromford`, made on 2026-10-11 with `git clone`. The run date in the header comes from `--now`, not from the clock.
