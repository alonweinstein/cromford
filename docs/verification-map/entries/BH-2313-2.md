| queue-rows flip preflight, merge gate (BH-2340 / BH-2313.2): `bin/lib/qrf/merge.sh`, the `merge_queue_rows_only` check run by `bin/queue-rows-flip-preflight.sh merge`. Per project directory under `state/merge-queue/` it lists the live statuses (BH-3221): GET `/api/merge-queue?project=<p>&status=queued&limit=500` and `…&status=blocked&limit=500`, array `.merge_queue`. It does not send the rows-only reader's unfiltered `mq_queue_list` → `merge_queue_list <p>` read, because the worker keeps landed/dropped rows and that list sits at its default limit of 200; the route cannot page, so a live status at 500 rows is incomplete. It checks the live rows are a superset of the files: a plain `<pr>` needs a `queued` row, a `<pr>.blocked` needs a `blocked` row (it shadows a plain `<pr>`), `*.absent` and non-numeric names are skipped; a file whose row is landed/dropped reads as having no row; a queued/blocked row with no file is info, never a FAIL; with no project directory it sends one GET `/api/merge-queue?status=queued` liveness probe | none (no UI); operator-run on each `fleet.conf` box that holds `state/merge-queue/`; no cron line | probe: `HARNESS=/root/harness bin/queue-rows-flip-preflight.sh merge`. READY prints `[PASS] live probe /api/merge-queue?project=<p>&status=<queued|blocked>&limit=500 http=200 rows=<n>` (one per status), `[PASS] row parity <p>: <n> file(s) matched` per project and `RESULT: READY merge`, exit 0. NOT READY prints `[FAIL] merge: state/merge-queue/<p>/<file> has no row — fix: merge_queue_put <p> <pr>` (a `.blocked` file names `merge_queue_set <p> <pr> blocked`, after `merge_queue_put` unless the row is `queued`), `[FAIL] merge: live probe … http=<code>` on a 503/1101/HTML answer to either read (that project's parity is then `not checked`, never matched), or `incomplete: rows=500 = limit 500`, then `RESULT: NOT READY merge`, exit 1. GETs only, nothing written; proven by `tests/queue-rows-flip-preflight-merge.bh-2313-test.sh` and `tests/qrf-merge-live.bh-3221-test.sh` |
