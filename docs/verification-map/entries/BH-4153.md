Screen `console-ui/src/screens/Flags.js` (`FlagsScreen`), pure half `console-ui/src/lib/flags.js`. Reads `GET /api/coord/flags` every 60 s; writes `PUT /api/coord/flags {name, scope, value, active:1, reason}` (SET FLAG…) and `DELETE /api/coord/flags?name&scope&reason` (CLEAR; the proxy refuses a blank reason). NAME links to `/config/flag/<name>` (the history), PROJECT to `/p/<project>`, a box SCOPE to `/machines`. Box side: `bin/jobs-client.sh flag-has|flag-set|flag-clear|flag-list|flag-active <name>` (flag-active's stderr line names the source: `harness_flags row`, `cache (age Ns)`, `local hold`, or `unknown → read as ON`); `bin/flags-import.sh [--dry-run]`; the `# >>> flags import` block of `bin/update-runners.sh` logs `flags-import:` lines to `logs/update-runners.log`. Files on a live box: `state/flags-cache/<scope>/<name>`; after the first daily import `ls /root/harness/flags \| grep -E '^(paused-\|automerge-disabled\|lanedown-)'` is empty. Live check: one pause and resume from `/flags`, seen as `paused via console, skipping` then a normal tick line in `logs/<project>.log`. What usually lies: a `cache` source is the last good row, not the current one; `pause_flags` is a mirror for these names, never write it directly; a `failed` import line means the file is still there and still honoured.
