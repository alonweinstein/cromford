| /hub CHAT BINDINGS: which Telegram thread each project posts to, with an inline edit that moves one project to another thread (BH-2521.3 / BH-2678) | [2026-09-26-BH-2521-chat-bindings.md](../notes/2026-09-26-BH-2521-chat-bindings.md) | Nav: HUB (`/hub`) → scroll past RESTORE LAB and SEED REGISTRY → CHAT BINDINGS. A SortableTable (inside `.tablewrap`) with PROJECT (links to `/p/<project>`), THREAD, ACTOR, UPDATED and an unsortable edit column; REFRESH in the section head reloads once (no polling). EDIT turns the row's thread into `input[aria-label^="new thread id"]` with SAVE / CANCEL; an id that is not a positive integer, or the current id, is refused inline and sends nothing; a valid id opens `role=dialog[aria-label="CHAT BINDINGS"]` reading "Move <project> from thread A to B?" with a required REASON input and CANCEL / MOVE; MOVE is disabled until the reason is filled (BH-2995), then sends one PUT `{project, thread_id, reason}` and reloads. Routes: `GET`/`PUT /api/coord/telegram-topics` → worker `GET`/`PUT /api/telegram-topics` (`worker/jobs/src/routes/telegram-topics.js`, GET answers `{topics, rows, as_of}`), table `telegram_topics`. Precondition: at least one `telegram_topics` row; with none the section reads "No chat bindings yet", and a failed load shows "could not load" with RETRY.
