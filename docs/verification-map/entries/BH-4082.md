Reads `GET /api/coord/projects` (worker `GET /api/projects`, `worker/jobs/src/routes/projects.js`, `{projects, as_of}` ordered by project) and writes one row with `PUT /api/coord/projects` (allowlist row in `console-ui/functions/api/coord/[[path]].js`: project, repo, prod_url, board_api_prefix, cron_offset, box, tailnet_ip, note, reason; reason required, the proxy stamps the actor). The worker validates every column and answers 400 `{error}` with nothing written: project lowercased once and `^[a-z0-9][a-z0-9-]{0,63}$`, repo an `owner/name` slug, prod_url `https://…` or blank/`-` (stored NULL), board API path `/…` or blank/`-` (NULL), cron_offset a whole number 0-9 (refused, never clamped), box a lowercase slug or `local` or blank, tailnet address a dotted IPv4 or blank, no newline in any of those, note at most 512 characters. Each change batches one `config_changes` row (kind `project`, name = the project) with the upsert; an unchanged re-save writes none. There is no DELETE (405 at the proxy, unrouted at the worker). The table is `projects` in the jobs D1 (`worker/jobs/schema.sql`, self-created from `CREATED_TABLES`); it ships EMPTY and NOTHING in `bin/` reads it yet, so editing a row does not change `fleet.conf` on any box (the page's explainer says so). Selectors and states are the CONTROLS editor's (see the BH-2513 row): `th[aria-sort] button` per field, the identity cell links to `/config/project/<project>` (its change history), EDIT/NEW open the in-app Modal with a `type=number` triage-minute input, zero rows is "no Projects rows on record yet".
