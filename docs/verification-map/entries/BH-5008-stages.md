| Merge-queue stages: waiting line and per-PR stage track (BH-5669, BH-5008 child 3) | `/merge-queue` (and `/merge-queue?project=<name>`): under the batch section, the section `WAITING TO BE BATCHED` is a `SortableTable` (`.tablewrap table.tbl`) with the columns POSITION, PR, REPO, QUEUED AT, sorted by position by default. Each PR cell is an `<a href="https://github.com/<repo>/pull/<n>">`, plus a `/t/<key>` link when a `pr_owners` row maps the PR to a ticket. The section renders nothing when nobody waits, an error box on a load failure, and a "List may be incomplete" note on `complete:false`. `/jobs` and `/t/<key>`: in the JobsTable TICKET cell, a compact six-station track (`.track-scroll .track[aria-label]`, stations Queued, In batch, Checks, Merging, Merged, Deploy verified), then one line per failure, each an `<a>` to the check run or the draft: `Failing: <check>`, `Splitting: testing #a, #b, step s of S`, `Dequeued: <check> failed on #n alone` | `GET /api/coord/merge-queue/live[?project=]` (`worker/jobs/src/routes/merge-queue-live.js` → `applyStages` in `src/lib/merge-queue-live-stages.js`) sets each batch's `stage`, `failing{name,url}` and `bisect{step,steps,parent}`, `prs["<repo>#<n>"] = {stage, detail, batch, at, key, project}` from each PR's newest `pr_state_events` `state='queue'` row of the last 24 h, and `waiting[{repo, pr, position, at, key}]` from the `queued (<n>)` rows, by position. The rows come from the signed github webhook through `stageStatements` (`src/lib/merge-queue-intake-stages.js`): `batched` on draft open, `checking` on a check, `merging` on a green check suite when every stored check of the draft is completed and none failed, no `checking`/`merging` on a closed batch, `merged` on a close with `merged === true`, `dequeued` on a failed check of a 1-member bisect draft. A bisect draft (members a strict subset of a failed batch's) gets `bisect_parent/step/steps` on `merge_queue_batches`. The intake never writes `queued` or `deploy_verified`; until a writer for `queued (<n>)` rows lands, the waiting line is empty. Preconditions: the repo is armed (`projects` row or `merge_queue_repos`); a ticket-key track needs a `pr_owners` row for the PR. Every track on a page shares one request per 5 s.
