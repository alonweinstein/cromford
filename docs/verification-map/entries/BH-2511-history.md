The table is a `SortableTable wide`, default WHEN descending, every header a sort button with aria-sort: WHEN (date + `HH:MMZ`, title the raw `at`, sorted on the raw ISO string), KEY (a button: click re-reads `?key=<key>&limit=200` and shows only that key's rows), BEFORE (`—` for a created cap), AFTER, ACTOR, REASON (`—` when none). An active filter shows a `key: <key>` chip and a "clear filter" button that re-reads without `key=`. States: loading skeleton (also while the answer for a new filter is in flight); failed read is the ErrorBox with RETRY, never the empty copy, and a failed refresh keeps the last rows under it; a body without a `changes` array is the ErrorBox "unexpected response from /api/coord/cost-cap-changes"; zero rows reads "no cap changes yet" ("no cap changes for <key> yet" when filtered); "showing the newest N" only when the body says `truncated: true` |
