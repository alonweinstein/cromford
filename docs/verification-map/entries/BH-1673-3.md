| Mergify queue-time measurement (BH-1673.3): how long the last N merged PRs of a repo waited between entering the merge queue and merging, read over GitHub REST only | [../MERGIFY.md](../MERGIFY.md) | `bin/mergify-queue-time.sh <owner/repo> [--last N]` (N defaults to 20; operator-invoked, no cron caller). One TSV row per merged PR, newest `merged_at` first: `pr queued_at merged_at minutes source`, where source is `queued` (the last Mergify `queued` label at or before merge), `merge-queue` (our label, the fallback), `none` (never queued) or `error` (its events read failed). The final line is `median_minutes=<x\|none> measured=<k> unqueued=<u> wanted=<N> incomplete=<0\|1>`: the median over measured rows only, `unqueued` counts `none` rows and never a failed read, and `incomplete=1` (fewer than N merged PRs on the one pulls page, a failed events read, or a full 100-event page) means do not trust the median as final. rc 75 with no output = the pulls read failed or any read was rate limited; rc 2 = usage. Verified by `tests/mergify-queue-time.bh-1700-test.sh` (stub `gh`, the real CLI) |
