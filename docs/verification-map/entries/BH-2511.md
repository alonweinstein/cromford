| Cost caps table (BH-2511, BH-2566) | Nav COSTS → /costs → CAPS (directly below COST BREAKER) | Read `GET /api/coord/settings`, polled every 60s; every `conf.cost-caps.*` and `conf.lane-caps.*` row is one table row. CAPS is a `SortableTable wide` (scrolls inside its own container at 375px): SCOPE (project/lane/fleet, plus ` · box <b>` for a box-suffixed key), SUBJECT (project → `Link` to `/p/<project>`, lane → `Link` to `/settings/<lane>`, fleet keys plain text), KIND (`cost-caps.budget`, `lane-caps.noise`, …), CATALOG (the `registry-seed` row's value, else `—`), OVERRIDE (an operator row's value, else `—`), APPLIES (override, else catalog), BY, UPDATED (relative, ISO on hover), EDIT; default SCOPE ascending. EDIT is offered on fleet rows only; box-suffixed and unknown-shaped keys read "display only". EDIT opens the in-app Modal "EDIT CAP": the key, a VALUE input (focused on open, prefilled with APPLIES) then a REASON input, the kind's grammar and a hint; SAVE stays disabled until the reason is non-blank and the value parses (same grammar as `bin/lib/cost-budget.sh` / `bin/lib/lane-caps.sh`); Escape cancels with no request. SAVE sends `PUT /api/coord/cost-caps {key,value,reason}`; the proxy stamps `actor=console`. Success reads "cap <key> set to <value>" and reloads the table; failure reads "EDIT failed — <worker error>" and does not reload ("EDIT failed — not implemented" while the worker route is the BH-2563 stub). States: Skeleton while loading; a failed settings read is the ErrorBox, never the empty copy; no cap rows is "no cap rows yet — run bin/cost-caps-seed.sh on the hub". Footnote always: "a box-local flags/cost-caps.conf or flags/lane-caps.conf is not visible here; an override row beats it" |
