| CI health panel (BH-2634) | Nav CI → /ci; a repo → /ci?repo=<slug> (slug URL-encoded, e.g. `/ci?repo=example-org%2Fcromford`) | Three reads through the coord proxy, each polled every 60s: `GET /api/coord/ci-health`, `GET /api/coord/metrics/flakes?since=<today-7d>&limit=2000`, `GET /api/coord/metrics/flakes/quarantine?active=1`. CI HEALTH is a `SortableTable wide` (REPO `Link` to `/ci?repo=<slug>`, MINUTES 24H, RUNNERS online/total, FLAKES 7D and FLAKE RATE in distinct heads, QUARANTINED); a missing value is `span.na` "—" titled `unread` or `not pushed`, never 0. Skeleton until every read answers; all three failed is the ErrorBox (worker offline, or the ci-health/quarantine routes not deployed yet); some failed is a footnote per failed read ("minutes and runners unreadable: …", "quarantine unreadable: …") over the table; a "first 2000 flake rows only" note at the worker's limit; zero rows is the Empty "no CI health pushed yet". With `?repo=` a FLAKES · <repo> section adds `GET /api/coord/metrics/flakes?repo=&since=&limit=2000` and `GET …/quarantine?repo=&active=1`: a `SortableTable` (TEST button with `aria-expanded`, FLAKY HEADS, LAST SEEN, QUARANTINE ON/OFF tag plus an ON/OFF button, disabled with a title for `job:`/`workflow:` names and when the quarantine read failed); empty "no flaky tests for <repo> in the last 7 days"; a failed flakes read is the ErrorBox. Clicking a TEST opens HISTORY · <test> from `GET /api/coord/metrics/flakes/quarantine/changes?repo=&test=&limit=50` (WHEN, CHANGE `off → on` / `— → on`, ACTOR, REASON; newest first; empty "no quarantine changes yet"). The toggle opens the in-app Modal (focus in the REASON input, confirm disabled until the reason is non-blank, Escape cancels with no request) and sends `PUT /api/coord/metrics/flakes/quarantine` with `{repo, test, active, reason}`; the proxy stamps `actor`. Success needs the worker's `ok: true`, shows a `role="status"` banner and reloads; anything else shows "quarantine failed — <error>" and does not reload. MERGE-QUEUE BATCHES (BH-4972), always below CI HEALTH, adds a fourth read polled every 60s: `GET /api/coord/ci-batches?[repo=<slug>&]since=<today-30d>&limit=5000` (BH-4971's ledger; `?repo=` scopes it, none reads every repo). Skeleton until it answers; a failed read or a payload with no `rows` array is the ErrorBox with RETRY (an unapplied table shows "ci_batches schema not applied" there, and the rest of /ci still renders); zero rows is the Empty "no merge-queue batches recorded yet" with no median line. With rows: the line "7-day median batch minutes: before X (n) · after Y (n)" (billed minutes of every batch in the 7 days either side of the first `batch-selected` batch; a side with no measured batch reads "not enough batches yet", or "before the loaded window" when the 30-day read or a truncated read cut it), a "first 5000 batches only" footnote when the read is truncated, then a `SortableTable wide` newest first: RUN (`#<run_id>` link to `https://github.com/<repo>/actions/runs/<run_id>`, new tab; plain text titled "repo unreadable" when the repo or id is not readable), WHEN, MODE, SELECTED / TOTAL (`12 / 340`, "—" for a missing count), ESCALATION (reason text, "—" for none), DURATION, BILLED min, CONCLUSION; every header sorts on the shown value with aria-sort, missing values sink. |
