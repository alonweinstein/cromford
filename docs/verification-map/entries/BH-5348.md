| Participant machines in Mission Control: approve, deny and revoke enrollment, browse enrolled machines and their claims (BH-5353) | [../notes/2026-10-08-BH-5353-participants-screen.md](../notes/2026-10-08-BH-5353-participants-screen.md) | Nav FLEET → MACHINES → SEE PARTICIPANTS (`/machines/participants`); a NAME cell opens `/machines/participants/<id>`. Selectors: `[data-testid=participant-pending]` (one card per pending row, a checkbox per requested role, buttons APPROVE and DENY; APPROVE is disabled with every role unticked), the ENROLLED table's NAME links (`a[href^="/machines/participants/"]`), LAST RESULT links (`/pr/<project>/<n>`), the detail's REVOKE (approved rows only), and the confirm dialog's `.modal__actions` buttons (CANCEL, APPROVE / DENY / REVOKE). States: no rows → `no machines enrolled`; a failed load → `could not load` with RETRY; an unknown id → `no such participant`; a refused decision → a warn banner with the worker's text. Routes `GET /api/coord/participants`, `GET /api/coord/participants/<id>`, `POST /api/coord/participants/<uuid>/approve` (`{granted_roles}`), `…/deny`, `…/revoke`. Preconditions: one pending and one approved row in `participant_machines` (a machine enrolls with `POST /api/participants/request`); `LEAD_VERDICT_TOKEN` set on the console Pages project, else every decision answers 503 naming it.
