# Lane runs on Fly: the queue contract (BH-6124)

**What it is:** a lane can run on Fly machines instead of the hub. A settings
row decides where. For a lane placed `fly`, `pl_dispatch` enqueues one
`lane_runs` row per project, and `bin/lane-run-worker.sh` on a machine claims
it, runs it and reports its rc. Every lane stays on the hub by default.
Details: [the note](../notes/2026-10-12-BH-6124-lane-runs.md).

- Placement (`bin/lib/lane-placement.sh` `lp_decide`): row
  `lane_placement.<lane>`, else `lane_placement.default` (seeded `hub`). Only
  `fly` (trimmed, lowercased) is fly. A `lane_placement.<lane>.hub_only` text
  keeps the lane on the hub.
- Dispatch (`bin/lib/project-lanes.sh` `pl_dispatch`): the summary line ends
  `; placed: <n> fly, <m> hub (<reason>)`, then `, <k> already live` and
  `, <f> enqueue failed -> hub` when non-zero. A failed enqueue runs the
  project on the hub and writes ONE alert, id `lane-placement:<lane>`.
- Queue (harness-jobs, `worker/jobs/src/routes/lane-runs.js`):
  `POST /api/lane-runs`, `POST /api/lane-runs/claim`,
  `POST /api/lane-runs/<id>/report`, `GET /api/lane-runs/stats?lane=`.
  Table `lane_runs` (`worker/jobs/schema.d/0020-bh-6047-lane-runs.sql`). Rows
  `lane_run.lease_s` (120) and `lane_run.poll_s` (15).

**How to drive it:**

| what | how |
|---|---|
| dispatch, placement and the machine loop, over the real worker | `HARNESS_TEST_SANDBOX=1 bash tests/project-lanes-fly.bh-6124-test.sh` |
| the routes alone | `cd worker/jobs && node --test test/lane-runs.bh-6124.test.js` |
| one lane's placement on a box | `HARNESS=/root/harness bash -c '. bin/lib/project-lanes.sh; lp_decide <lane>; echo "$LP_PLACE $LP_WHY"'` |
| the queue on a live worker | `curl -sS -H "authorization: Bearer $HARNESS_SECRET" "$JOBS_URL/api/lane-runs/stats"` |
| on a live box | `grep 'placed:' logs/<lane>-cron.log`; `tail logs/lane-run-worker.log` |

**What must never regress:**

- With no `lane_placement.<lane>` row and the seeded default, every lane runs
  on the hub exactly as before (F5).
- A held project is never enqueued (F1).
- A row is `done` only from its claimer with an integer rc 0..255 (W5, F2).
- A failed enqueue never drops a project: it runs on the hub (F8).
